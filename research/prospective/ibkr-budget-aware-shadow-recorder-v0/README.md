# IBKR Budget-Aware M1C Shadow Recorder V0

This is a research-only, record-only extension of the existing frozen M1C
prospective recorder. It constructs completed five-minute bars from one audited
IBKR bar stream per frozen-universe symbol, scores the exact frozen causal M1C
runtime, captures bounded option top-of-book evidence immediately, and compares
later EODHD reconstructions without requiring vendor OHLC equality.

**RESEARCH ONLY — RECORD ONLY — NO ORDERS**

The historical quiet-state conclusion remains
`blocked_insufficient_low_tail_support`. This implementation does not claim that
the frozen historical raw-checkpoint concentration gate passed.

## Capacity architecture

Startup resolves observable IBKR capacity first and then uses explicit
environment or configured fallbacks for limits IBKR cannot expose. The result is
written to `ibkr_runtime_capacity_manifest.json`, including provenance, external
usage, current internal usage, a safety margin, and the 12-line future-trading
reserve. The discovered or configured historical-bar allowance is enforced by
a rolling-window pacer during startup and reconnect restoration.

The always-on design requests one bar stream for each of the 20 frozen stocks
plus only required proxies. Level I is promoted for an armed or active episode.
One active option episode, eight continuous option lines, two concurrent
discovery snapshots, and one tick-by-tick underlying are the defaults. Level II
is disabled. Optional classes 5, 4, then 3 are shed before critical signal
streams; optional exhaustion queues, reduces, records, or skips work without
stopping frozen M1C recording.

Missing external scientific inputs do not make the IBKR acquisition process
disappear. When the production bar-compatibility report, historical activity
baseline, or exact previous-session Group O package is absent, the process keeps
the minimal bar streams and connection audit online while persisting a specific
scientific blocker. M1C scoring and episode-triggered option recording remain
disabled; a missing input is never replaced with a fabricated pass artifact,
stale context, or an outcome-informed substitute.

## Scientific tracks

- Track A compares IBKR and later EODHD bar semantics, causal features,
  probabilities, tail membership, and episode identity for 20 valid sessions.
- Track B records bounded IBKR option and promoted-underlying engineering data.
- Track C records conservative frozen-M1C option shadow outcomes.

All option records in the first 20 valid sessions are
`cohort_phase=engineering_transfer` and
`scientific_option_evidence=false`. Phase 1 cannot open until a supported
source-transfer decision is persisted.

## Running

Use `configs/prospective/server.example.yaml` as the deployment template. The
IBKR connection must be loopback, read-only, and market-data-only. Relevant
capacity overrides are documented in `deploy/stocker.env.example`.

The web application exposes read-only budget, source-transfer, universe,
episode, and report-package endpoints. It has no order, account, position,
portfolio, buy, or sell route.

## Reports

Every session produces an append-only generation containing the 14 files in
`schema_manifest.json` and a ZIP suitable for ChatGPT review. The cumulative
transfer report never makes a strategy-profitability decision. A distribution-
only `M1C_IBKR_CALIBRATION_V1_CANDIDATE` can be frozen only when ranking
transfers but the probability scale shifts; V0 continues in parallel.

## Verification

Focused tests cover capacity discovery and fallback, the protected reserve,
priority shedding, canonical subscription ownership, reconciliation, bounded
option allocation, DTE rules, transfer metrics, phase gating, reports, fake
adapter scenarios, reconnect handling, and deterministic replay. The independent
audit is generated by `run_independent_audit.py`.
